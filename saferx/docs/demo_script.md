# 答辩演示脚本（90 秒动线 + 兜底方案）

> 目标：在 90 秒内把「查得准 → 看得懂 → 抽得出」讲完整，并主动交代数据边界。
> 全部操作在单服务 `http://127.0.0.1:8000` 完成，无需联网。

## 0. 演示前置（开讲前 3 分钟做完）

```bash
cd saferx
make prod            # 建库 + 前端构建 + 单服务启动（0.0.0.0:8000）
# 浏览器打开 http://127.0.0.1:8000 ，确认首页数字为 1,971 / 234,981 / 366
```

检查清单：

- [ ] `curl -s http://127.0.0.1:8000/api/health` 返回 `status: ok`
- [ ] 浏览器缩放 100%，窗口宽 ≥ 1280（六页导航不折行）
- [ ] 药单徽标显示 `0`（干净状态，避免上一场残留）
- [ ] 备用终端已 `cd saferx`，随时可重启
- [ ] `deploy/screenshots/` 已打开在一个标签页（断网兜底）

## 1. 动线（90 秒）

| 时间 | 操作 | 画面 | 话术要点 |
|---|---|---|---|
| 0–12s | 停在首页，不点击 | 数据规模条：1,971 药 / 234,981 药对 / 366 中文名 / <5ms | 「数据不是演示条数，是 DDInter 2.0 全量清洗入库：19 万+ 药对，检索式检查平均 2.5 毫秒」 |
| 12–28s | 点「高血压 + 房颤」卡的 **载入药单并预检** | 跳到「我的药单」，5 个药盒胶囊 chip，右侧风险环出现红/琥珀分段 | 「一次载入整张处方——这是和官网单药查询最大的区别：**处方级检查**」 |
| 28–32s | 停留在药单页，指右侧摘要 | Major 2 / Moderate 3 等计数 | 「左边增删药，右边实时重算，聚合策略是同一组合取最高级——宁可高报不漏报」 |
| 32–45s | 点 **开始完整检查** | 结果页：环形图 + 风险卡片列表 | 「华法林 + 胺碘酮是 Major：CYP2C9 抑制导致 INR 升高，处置建议是减量并监测 INR」 |
| 45–55s | 展开第一条卡片 | 机制 / 处置 / 证据溯源（`DDInter2.0:ID/ID`） | 「每条结论都能溯源到具体药对 ID，不是大模型生成的——医疗场景里可追溯性优先于覆盖面」 |
| 55–62s | 点 **交互图谱** | 力导向图，红边连高危节点 | 「红色边 = Major，节点描边是它涉及的最高风险；点击节点看详情」 |

| 88–90s | 点 **关于** | 数据覆盖与已知局限四张卡 | 「最后交代边界：中文名 18.6%、机制 21 条、分级未知 18%，**查不到 ≠ 安全**」 |

## 2. 备用方案（按故障类型）

| 故障 | 处理 |
|---|---|
| 后端进程挂了 | 终端 `make prod` 重启，约 15 秒；期间继续讲架构图 |
| 数据库缺失 / 首页数字为 0 | `make data && make initdb`（首次约 3–5 分钟，建议提前做） |
| 前端白屏 | 打开 `deploy/screenshots/01-home.png` 起逐张讲，话术不变 |
| 完全断网 | 无需处理——SQLite、静态资源、模型全本地；若前端显示「离线演示数据」徽标，说明后端未起，按上一条处理 |
| 图谱不渲染 | 切到 `deploy/screenshots/04-graph.png`；真实原因是 ECharts chunk 未加载完，等 2 秒即可 |

## 5. 预判提问（一句话版）

| 提问 | 回答 |
|---|---|
| 和 DDInter 官网有何区别 | 官网英文单药查询；本系统中文、处方级两两检查、图谱化、可离线部署 |
| AI 体现在哪 | 药名归一化（NLP）、文献三元组抽取（扩库）、事件预测（规划）；判断层刻意用审编库保证可溯源 |
| 为什么不用 LLM 判断 | 幻觉不可控、证据不可溯；LLM 只做低风险任务且需人工抽检 |
| 查不到是否安全 | 不是，界面与报告固定标注「未收录 ≠ 无相互作用」，并列出未收录组合 |
| 30 万条性能如何 | 无序对规范化 + 复合唯一索引；10 药 45 组合 2.47ms，20 药 190 组合 8.97ms |
| 数据会过期吗 | 管道可重跑，`make data && make initdb` 即升级；页面常驻数据版本与构建时间 |
